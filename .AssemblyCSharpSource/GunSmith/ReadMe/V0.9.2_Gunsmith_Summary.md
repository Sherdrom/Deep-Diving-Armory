# Gunsmith V0.9.2 Summary

## Goal

V0.9.2 simplifies GunSmith configuration ownership.

`platform` now describes platform rules only. Concrete default assembly starts from weapon root parts and recursively expands through `mount.defaultPart`.

## Result

Implemented scope:

- Removed current config usage of `platform.defaults`, `weapon.defaults`, and `rootAccepts`.
- Added `weapon.rootParts` for root identity parts such as the receiver.
- Added `mount.defaultPart` for recursive default child assembly.
- Replaced platform `slots / requiredRootSlots / hiddenRootSlots` config with `rootSlots`.
- Renamed `Config/Parts/AR/RootCommon/` to `Config/Parts/AR/Structural/`.
- Runtime default creation now uses `Core.BuildDefaultSelection`.
- Replacing a part now clears old descendants, then expands the new part's mount defaults.
- Validation now checks `rootParts`, `mount.defaultPart`, root socket coverage, removed config fields, and default tree cycles.
- Renamed schema fields to separate UI path from part type:
  - `part.slot` -> `part.type`
  - `mount.slot` -> `mount.path`
  - `mount.partSlot` -> `mount.partType`
  - `platform.slotNames` -> `platform.pathNames`

## Schema

Weapon config now only declares the root identity part:

```lua
rootParts = {
    receiver = "hk416_receiver_std"
}
```

Receiver mounts own their default structure:

```lua
mounts = {
    { path = "barrel", accepts = { "AR_barrel" }, defaultPart = "hk416_barrel_std" },
    { path = "handguard", accepts = { "AR_handguard" }, defaultPart = "hk416_handguard_std" },
    { path = "pistol_grip", accepts = { "AR_pistol_grip" }, defaultPart = "hk416_grip_std" },
    { path = "stock", accepts = { "AR_stock" }, defaultPart = "hk416_stock_std" },
    { path = "receiver_top_rail", accepts = { "AR_top_rail" }, defaultPart = "AR_receiver_top_rail" }
}
```

`defaultPart` is declared on the direct child mount. Runtime expands it into full paths such as `receiver/barrel`.

If the visible UI path should differ from the compatible part type, use `mount.partType`:

```lua
{ path = "rear_optic_mount", partType = "optic_mount", accepts = { "small_optic" } }
```

That shows/saves the path as `receiver/rear_optic_mount`, while listing installable parts with `type = "optic_mount"`.

Platform root slots are now explicit objects:

```lua
rootSlots = {
    { path = "receiver", required = true, hidden = true }
}
```

## Platform Role

The AR platform now carries:

- canvas and visual scale settings
- root slot rules
- required nested structure slots
- path display names

It no longer describes the default M4-like assembly. This keeps shared compatibility centered on `mount.accepts` and `part.provides`.

## Validation

Validation now reports errors for:

- removed config fields still present in current configs
- missing required `weapon.rootParts`
- unknown root part paths
- missing or invalid `rootSockets`
- `mount.defaultPart` referencing missing child parts
- default child type or provides/accepts mismatches
- recursive default part cycles

## Known Limits

- V0.9.2 does not migrate old V0.9/V0.9.1 saved state.
- Root identity parts remain hidden from normal UI replacement.
- `mount.defaultPart` values are applied on initial build and when installing a new parent part; they are not re-added after a player explicitly removes an optional child from saved state.
