# Gunsmith V0.5 Summary

## Goal

V0.5 turns the working `deep_m4` prototype into a stricter GunSmith configuration framework.

This version does not add a second weapon, stat effects, multiplayer authority, a workbench entry point, or final art. The focus is schema cleanup, explicit compatibility, item boundary rules, and validation.

## Schema

V0.5 removes the old flat part fields:

- `texture`
- `source`
- `offset`
- `order`
- `itemIdentifier`

Parts now use:

```lua
visual = {
    texture = texture,
    source = { x = 0, y = 0, w = 0, h = 0 },
    offset = { x = 0, y = 0 },
    order = 0,
    scale = 1.0
}
```

and:

```lua
item = {
    identifier = "deep_gunsmith_part_identifier"
}
```

or:

```lua
item = {
    virtual = true
}
```

Parts without `visual` are valid logic/text parts and do not contribute to sprite composition.

`visual.scale` controls the rendered size of an individual part. Platforms may declare `visualScale` for platform-wide sizing, `visualOrigin` for the platform scaling pivot, and weapon entries may declare `scale` for weapon-specific overrides such as `weapons.deep_m4.scale`.

Runtime layer composition multiplies all three values:

```text
platform.visualScale * weapon.scale * part.visual.scale
```

The combined platform/weapon scale also scales visual offsets around `platform.visualOrigin`, defaulting to the canvas center when omitted.

Art completeness is intentionally not checked in V0.5. A later art pass should add a dedicated check for missing visual layers, missing texture files, invalid source rects, and incomplete offsets/orders.

## Compatibility

Slot-only fallback was removed.

Root slots declare accepted part types through `platform.rootAccepts`.

Child mounts declare accepted part types through `mount.accepts`.

Parts declare their type through `part.provides`.

Installation now requires:

- a valid path
- matching `part.slot`
- at least one match between `accepts` and `provides`

The UI shows incompatible parts as `[不兼容]` and clicking them does not change state.

## Item Rules

Default parts listed in `platform.defaults` are weapon-native parts.

- default parts do not require items
- installing a default part does not consume an item
- removing a default part does not return an item

Entity-backed parts use `item.identifier`.

- installing consumes one inventory item
- removing, replacing, or recursively unloading returns the item

Virtual parts must explicitly use `item.virtual = true`.

- installing does not consume an item
- removing does not return an item

Non-default parts without `item.identifier` or `item.virtual = true` are configuration errors.

## Validation

V0.5 adds Lua-side validation through `Lua/Scripts/Gunsmith/Validation.lua`.

Validation checks the major framework invariants:

- required config tables exist
- weapons reference valid platforms
- platforms define `slots`, `defaults`, `canvas`, and `rootAccepts`
- defaults point to valid matching parts
- parts define `slot`, `name`, and `provides`
- old fields are no longer used
- non-default parts define a real or virtual item rule
- mounts define `slot` and `accepts`
- declared `visual` data is complete

Warnings are reserved for soft problems such as missing item prefabs or unused compatibility types.

No warning is emitted for parts that simply omit `visual`.

Validation can be triggered from the console:

```text
DeepGunsmithValidate
```

An intentional broken-config self-test is also available:

```text
DeepGunsmithValidationSelfTest
```

The self-test builds a temporary invalid config and does not mutate the real `Gunsmith.Config`.

Validation also runs automatically during Lua startup as `Startup` after a short delay, so first-load config errors are visible without manually entering a command.

## Runtime Notes

Runtime sprite composition only reads `part.visual`.

Inventory code only reads `part.item.identifier` and `part.item.virtual`.

Persistence prunes old saved states that no longer pass explicit compatibility rules.

## Build Notes

Validated build command:

```text
dotnet build .AssemblyCSharpSource/GunSmith/GunSmith.sln -m:1 /p:UseSharedCompilation=false
```

The single-threaded command avoids transient Windows file locks from the shared C# compiler during local builds.
