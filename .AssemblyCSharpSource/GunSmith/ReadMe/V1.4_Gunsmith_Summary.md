# Gunsmith V1.4 Summary

V1.4 moves the current attachment affliction stats into GunSmith-owned part data for the M4/HK416 validation path. GunSmith now treats `part.stats` as the single source of truth for attachment attributes, while old XML afflictions remain available for non-GunSmith weapons.

## Completed

- Normalized attachment stats into `part.stats`.
  - Removed the temporary `LegacyEffects` layer and all `effects.legacy` references.
  - Migrated sight, grip, muzzle, and underbarrel values from `Afflictions/afflictions.xml` directly into GunSmith part configs.
  - Covered the active optic/grip/muzzle/underbarrel validation set used by M4 and HK416.
  - Removed the unused `Weight` and `RecoilControl` fields from Lua stats, runtime stats, UI formatting, and localization.

- Aligned Lua and C# stat schemas.
  - `Stats.Keys` now includes GunSmith `Ergonomics` plus all usable Barotrauma `StatTypes` enum names.
  - `GunsmithRuntimeStats` stores Barotrauma stats in a `StatTypes` keyed payload instead of a fixed field list.
  - Startup validation checks `part.stats` keys against `Stats.Keys`.

- Split runtime state from sprite state.
  - `GunsmithSpriteState` now only represents composed sprite data.
  - `GunsmithRuntimeState` stores runtime stats and managed item identifiers.
  - `DeepGunsmithApply` accepts an optional managed item identifier spec for backward-compatible runtime updates.

- Added GunSmith runtime stat application.
  - `Character.GetStatValue` contributes GunSmith-held weapon values for all Barotrauma `StatTypes` present in the runtime payload.
  - GunSmith spread, damage, fire-rate, skill, movement, resistance, gain, sound range, max-health, and future Barotrauma stat modifiers now flow through the same runtime stat payload.

- Reworked quick-slot duplicate suppression.
  - Suppression is driven by installed `part.item.identifier`, not affliction identifiers.
  - C# no longer hardcodes attachment affliction IDs such as sight, grip, muzzle, or underbarrel affliction names.
  - Status effects with afflictions are suppressed only when the source item is inside a GunSmith weapon container and that item identifier is currently managed by the weapon state.
  - Non-GunSmith weapons continue using the original XML affliction behavior.

- Kept HK416 QuickMod behavior compatible.
  - Real ItemContainer slots remain in use for the HK416 quick-mod bridge.
  - Original `RequiredItems type="Contained"` behavior is preserved for functional attachments such as underbarrel weapons.
  - Managed attachment stat afflictions are prevented from stacking with GunSmith runtime stats.

- Updated GunSmith UI stat display.
  - Part details show non-zero `part.stats` values instead of placeholder values.
  - The detail stat list is scrollable so long attachment stat sets do not overflow the right panel.
  - The attempted preview-image/description detail panel was reverted; UI design for richer part inspection is deferred.

## Deferred

- Full server-authoritative GunSmith state and stat synchronization.
- Exact health-resistance parity for stat effects that do not map cleanly through `Character.GetStatValue`.
- Wider weapon migration beyond the current `deep_m4` and `deep_hk416` validation scope.
- A redesigned right-side part detail panel with preview art and descriptions.

## Compatibility Notes

- V1.4 does not remove old affliction definitions from `Afflictions/afflictions.xml`.
- GunSmith parts now own their stats through `part.stats`; old affliction identifiers are not part of GunSmith framework configuration.
- Duplicate suppression uses real item identifiers, so cases where item ID and affliction ID differ remain supported.
- Old calls that do not pass managed item identifiers are treated as an empty managed-item set.
