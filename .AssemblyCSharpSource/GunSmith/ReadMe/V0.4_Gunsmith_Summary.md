# Gunsmith V0.4 Summary

## Goal

V0.4 changes Gunsmith from a pure state selector into an item-driven customization flow.

The target is:

- parts can be represented by real Barotrauma items
- installing a physical part consumes that item
- removing or replacing a part returns the old item
- recursive child parts are returned when an upper part is removed
- the V0.3 saved state continues to store installed part IDs on the weapon

This version still focuses on `deep_m4`. It does not add multiplayer authority, stat effects, final part art, a workbench entry point, or a second weapon platform.

## Result

V0.4 has been tested in game and confirmed working.

Confirmed working:

- `deep_m4` still opens GunSmith with `G`
- item-driven installation works for the first test parts
- missing physical parts are shown as unavailable in the UI
- installing a physical part consumes one matching item
- removing a physical part returns it to the character inventory
- replacing or removing upper parts recursively returns child parts
- runtime `InventorySprite` and `WorldSprite` still update correctly
- saved state still persists through `GunsmithData.SavedState`
- UI refreshes in place instead of rebuilding the whole window for normal part changes

## Test Parts

V0.4 introduces a minimal physical part test set in:

```text
weapon/part/gunsmith_parts.xml
```

Current test item bindings:

- `m4_handguard_alt` -> `deep_gunsmith_m4_handguard_alt`
- `m4_rail_short` -> `deep_gunsmith_m4_rail_short`
- `m4_red_dot` -> `deep_gunsmith_m4_red_dot`

These items are intentionally small validation items. They are not final art or final balance.

## Lua Changes

V0.4 adds:

- `Lua/Scripts/Gunsmith/Inventory.lua`
- part `itemIdentifier` support in `Config.lua`
- required root slot handling through `requiredRootSlots`
- install checks against the character inventory
- physical item consumption on install
- physical item return on remove or replacement
- recursive subtree return for nested mounts

The selection model remains path-based:

```text
handguard
handguard/top_rail
handguard/top_rail/optic_mount
```

C# still receives a flattened layer spec. C# does not understand the tree or physical item rules.

## UI Changes

The right panel now shows simple item-driven states:

- `[已安装]`
- `[可安装]`
- `[缺少配件]`
- `[不可拆空]`

Clicking unavailable rows does nothing.

UI refresh behavior was tightened:

- normal updates reuse the current window
- part list refreshes no longer rebuild the whole window
- returning to a parent path selects the slot that was just entered

This makes nested navigation less jumpy, especially around `护木 -> 上导轨 -> 瞄具挂点`.

## Runtime Safety

V0.4 also fixes a runtime texture crash found during Lua reload testing.

The crash was caused by an item still referencing a runtime composed `Texture2D` after that texture had been disposed.

The C# side now:

- checks runtime sprite state before reapplying it
- restores vanilla sprites if a runtime texture is no longer usable
- avoids drawing disposed runtime textures
- restores vanilla sprites during plugin disposal

The `Item.Draw` Harmony patch uses an explicit method signature to avoid ambiguous overload matching.

## Project Rename

The C# project was renamed from `GunsmithPatch` to `GunSmith`.

Updated areas:

- source folder: `.AssemblyCSharpSource/GunSmith`
- solution: `GunSmith.sln`
- assembly name: `GunSmith`
- root namespace: `GunSmith`
- mod assembly references in `ModConfig.xml`
- top-level deployed DLLs under `bin/.../GunSmith.dll`

The rename reflects the current direction: this is becoming a GunSmith framework, not just a patch.
