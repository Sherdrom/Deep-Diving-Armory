# Gunsmith V0.9 Summary

## Goal

V0.9 changes the weapon model from flat weapon root slots to a receiver-led tree.

In V0.8, AR root parts were all placed directly against `weapon.rootSockets`. This helped alignment, but it could not express that the handguard, barrel, grip, and stock should be positioned by the current receiver. V0.9 makes receiver the structural hub for AR weapons.

## Result

Implemented scope:

- AR platform root slots now contain only `receiver`.
- `barrel`, `handguard`, `pistol_grip`, and `stock` are mounted from the installed receiver.
- M4 and HK416 receivers provide structure mounts with local `anchor` coordinates.
- M4 receiver also exposes a receiver-level `optic_mount` for UI and schema validation.
- `weapon.rootSockets` only needs a receiver socket for AR weapons.
- `platform.defaults` and `weapon.defaults` now use full paths such as `receiver/handguard`.
- runtime world sprites now use the full composed texture instead of the original XML world sprite source rect, so long cross-weapon parts are not clipped.
- inventory sprites are generated from a separate compact texture with weapon-level scale, rotation, and padding controls.
- The old V0.8 save path shape is intentionally not migrated.

## Schema

AR now starts from a single root:

```text
weapon
  -> receiver
       -> barrel
       -> handguard
            -> top_rail
                 -> optic_mount
            -> bottom_rail
            -> left_rail
            -> right_rail
       -> pistol_grip
       -> stock
       -> optic_mount
```

Receiver parts provide the structural slots. `anchor` is relative to the parent part's `visual.attachPoint`:

```lua
mounts = {
    { slot = "barrel", accepts = { "AR_barrel" }, anchor = { x = 62, y = 44 } },
    { slot = "handguard", accepts = { "AR_handguard" }, anchor = { x = 62, y = 44 } },
    { slot = "pistol_grip", accepts = { "AR_pistol_grip" }, anchor = { x = -26, y = 74 } },
    { slot = "stock", accepts = { "AR_stock" }, anchor = { x = -68, y = 47 } }
}
```

Defaults use full selection paths:

```lua
defaults = {
    receiver = "M4_receiver_std",
    ["receiver/barrel"] = "AR_barrel_145",
    ["receiver/handguard"] = "AR_handguard_std",
    ["receiver/pistol_grip"] = "AR_grip_std",
    ["receiver/stock"] = "AR_stock_std"
}
```

## UI Behavior

`receiver` is hidden as a direct replacement option because it represents weapon identity.

The UI still promotes receiver child slots to the homepage. Players see entries like barrel, handguard, stock, and M4 receiver optic mount directly from the top level, while the internal saved paths remain nested.

## Sprite Output

The composed runtime texture remains the shared source for preview, inventory, and world sprites, but each output now chooses its own view:

- world sprite uses the full composed texture to avoid clipping parts that extend beyond the original XML source rect.
- inventory sprite renders a separate compact texture from the composed content bounds.
- `weapon.inventory` controls inventory icon presentation:

```lua
inventory = {
    scale = 0.55,
    rotation = 45,
    padding = 6
}
```

`rotation` is in degrees and only affects inventory icons. Preview and world display are unchanged.

## AK Direction

V0.9 does not add an AK platform, but the schema can represent one.

An AK receiver part can mean receiver plus fixed barrel, then expose `muzzle_device`, `handguard`, `pistol_grip`, and `stock` mounts directly. That avoids forcing AK into an AR-style independent barrel slot.

## Validation

Validation now supports nested defaults:

- default paths are sorted and checked from parent to child.
- root defaults use `rootAccepts`.
- child defaults use the installed parent part's `mounts.accepts`.
- defaults fail if the parent path is missing, the parent does not provide that mount, the part slot does not match the path leaf, or provides/accepts do not match.
- weapon inventory settings validate positive `scale`, numeric `rotation`, and non-negative `padding`.

`DeepGunsmithValidationSelfTest` includes intentionally broken nested defaults and root socket cases.

## Known Limits

- Muzzle devices are only a schema direction in V0.9; no muzzle device prefab or barrel mount is added yet.
- Stock remains `receiver/stock`; buffer tube and finer stock structure are deferred.
- HK416 receiver-level optic mounting is deferred until the receiver top rail is visually tuned.
