# Gunsmith V0.8 Summary

## Goal

V0.8 fixes visual placement when root parts are shared across weapons on the same platform.

V0.7 let child attachments follow parent mount anchors, but root parts still depended on a single absolute `visual.offset`. A first V0.8 draft tried `rootAnchors + relativeOffset`, but that still made each part's offset relative to one reference weapon. The final V0.8 model instead aligns a weapon socket to a part-local attach point.

## Result

Implemented scope:

- weapons now declare `rootSockets` for their platform root slots.
- root parts may declare `visual.attachPoint` in local source coordinates.
- root placement uses `weapon.rootSockets[slot] - visual.attachPoint`.
- child placement uses `parentDrawOffset + mount.anchor - child.visual.attachPoint`.
- `mount.anchor` is now interpreted as a parent-part local coordinate.
- M4 and HK416 both define AR sockets for `receiver`, `barrel`, `handguard`, `pistol_grip`, and `stock`.
- AR common parts, HK416 parts, rails, and optics now use `visual.attachPoint`.
- M4 receiver was moved into `Config/Parts/Weapons/M4.lua`; HK416 receiver remains in `Config/Parts/Weapons/HK416.lua`.
- receivers now use weapon-specific compatibility types (`M4_receiver`, `HK416_receiver`) with `weapon.rootAccepts` overrides, so the receiver acts as the weapon identity part.
- inventory, item prefab, compatibility, and stat behavior are unchanged.

## Schema

Weapon entries define platform-canvas root sockets:

```lua
rootSockets = {
    receiver = { x = 115, y = 27 },
    barrel = { x = 237, y = 45 },
    handguard = { x = 237, y = 39 },
    pistol_grip = { x = 101, y = 64 },
    stock = { x = 115, y = 27 }
}
```

Root sockets are validated against the weapon's current platform:

- every `platform.slots` root slot must have a matching root socket.
- root sockets cannot contain slots that the platform does not define.
- every socket must contain numeric `x/y`.

Parts define local attach points:

```lua
visual = {
    texture = texture,
    source = { x = 1234, y = 13, w = 48, h = 145 },
    attachPoint = { x = 0, y = 31 },
    order = 20,
    scale = 1.0
}
```

Placement priority:

1. root slot with `weapon.rootSockets[slot]` and `visual.attachPoint`: use `rootSocket - attachPoint`
2. child slot with parent `mount.anchor` and `visual.attachPoint`: use `parentDrawOffset + mount.anchor - attachPoint`
3. old anchor-relative fallback with `visual.relativeOffset`, for prototype compatibility

`visual.offset` has been removed from the active schema. Validation reports it as an error so new parts only have one current placement model.

## Validation

Validation now checks:

- `weapon.rootSockets` exists for each weapon.
- `weapon.rootSockets` covers every root slot in the weapon's platform.
- `weapon.rootSockets` does not declare unknown root slots.
- optional `weapon.rootAccepts` only references platform root slots and uses non-empty string arrays.
- weapon defaults are validated against weapon-level root accepts when a slot is overridden.
- root sockets, `visual.attachPoint`, optional `visual.relativeOffset`, and `mount.anchor` use numeric `x/y`.

`DeepGunsmithValidationSelfTest` includes bad, missing, and unknown root socket cases, bad weapon root accepts, plus bad attach point data.

## Known Boundary

V0.8 intentionally stops at fixed weapon root sockets. This solves many cross-weapon placement issues, but it does not yet model dependencies between root parts.

Example: HK416 handguards are longer than M4 handguards. If a long handguard is installed on another weapon, the barrel and muzzle relationship may still need a part-driven socket graph rather than independent weapon root sockets.

The likely next direction is to let the receiver provide sockets for barrel, handguard, grip, and stock, then let barrel provide a muzzle socket and handguard provide rail sockets. That would make the receiver the real structural hub instead of placing all root parts directly on the weapon.

## Notes For Next Version

Good next targets after V0.8:

1. tune M4/HK416 sockets and attach points after in-game visual passes
2. design a receiver-led socket graph for root-part dependencies
3. add barrel `muzzle` mounts and muzzle devices to validate length-dependent child anchors
4. decide whether to add a small calibration guide for future weapon authors
5. start planning stat gameplay effects, multiplayer authority, or workbench entry
