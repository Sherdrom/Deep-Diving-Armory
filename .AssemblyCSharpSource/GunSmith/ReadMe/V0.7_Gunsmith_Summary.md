# Gunsmith V0.7 Summary

## Goal

V0.7 validates that the GunSmith schema can support more than one weapon on the same platform.

This version adds `deep_hk416` as the second AR-platform validation weapon and turns the remaining non-default test parts into physical item-backed parts.

V0.7 still does not implement stat gameplay effects, multiplayer authority, workbench entry, or final art polish.

## Result

Implemented scope:

- `deep_hk416` is now registered as a `deep_gunsmith` weapon.
- `deep_hk416` has `GunsmithData` for per-item saved state.
- weapons may now declare weapon-level initial `defaults`.
- initial selections are copied from platform defaults plus optional weapon overrides.
- `deep_m4` starts from the original platform defaults.
- `deep_hk416` starts from its own receiver, barrel, handguard, pistol grip, and stock defaults.
- HK416 default visuals are assembled from slices of the existing `rifle_phy.png` HK416 source.
- all previous non-default virtual AR test parts now use physical item prefabs.
- default root parts also have item prefabs, and they follow the same consume / return rules as other physical parts when installed or replaced.
- platform-common parts now use `AR_*` Lua part ids and `deep_gunsmith_AR_*` item prefab identifiers.
- child attachment visuals can now follow parent mount anchors instead of relying only on platform absolute offsets.

## Schema

Weapon entries may now include:

```lua
defaults = {
    receiver = "hk416_receiver_std",
    barrel = "hk416_barrel_std",
    handguard = "hk416_handguard_std",
    pistol_grip = "hk416_grip_std",
    stock = "hk416_stock_std"
}
```

If omitted, the weapon starts from `platform.defaults`.

`Config.lua` is now a loader instead of a monolithic data file. GunSmith config data is split under `Lua/Scripts/Gunsmith/Config/`:

- `Platforms/AR.lua`
- `Weapons/AR.lua`
- `Parts/AR/RootCommon.lua`
- `Parts/AR/Attachments.lua`
- `Parts/Weapons/HK416.lua`

Runtime uses the initial defaults when:

- initializing weapon selections
- pruning invalid selections back to a valid default

Persistence now saves all root slot selections explicitly. Defaults are no longer used as a "free native part" or "do not save this root" rule.

Attachment visuals now support anchor-relative placement:

```lua
mounts = {
    { slot = "top_rail", accepts = { "picatinny_rail" }, anchor = { x = 276, y = 58 } }
}

visual = {
    texture = texture,
    source = { x = 635, y = 44, w = 100, h = 108 },
    offset = { x = 276, y = 58 },
    relativeOffset = { x = 0, y = 0 }
}
```

Root parts still use `visual.offset` as a platform-canvas absolute position. Child parts use `parent mount.anchor + visual.relativeOffset` when both are present, and fall back to `visual.offset` otherwise. Shared parts may keep a reference `visual.offset`; nested anchors on that shared part are shifted with the part when it is installed through a parent anchor.

## Physical Parts

The remaining V0.6 virtual test parts now have item identifiers and prefabs in `weapon/part/gunsmith_parts.xml`.

New AR physical bindings use the same naming pattern:

- `AR_receiver_alt` -> `deep_gunsmith_AR_receiver_alt`
- `AR_barrel_short` -> `deep_gunsmith_AR_barrel_short`
- `AR_grip_alt` -> `deep_gunsmith_AR_grip_alt`
- `AR_stock_alt` -> `deep_gunsmith_AR_stock_alt`
- `AR_rail_long` -> `deep_gunsmith_AR_rail_long`
- `AR_side_rail` -> `deep_gunsmith_AR_side_rail`
- `AR_right_rail` -> `deep_gunsmith_AR_right_rail`
- `AR_bottom_rail` -> `deep_gunsmith_AR_bottom_rail`
- `AR_holo_sight` -> `deep_gunsmith_AR_holo_sight`

Default parts are physical parts. Replacing an installed default part returns its item prefab, and installing that default part again consumes the matching item prefab. This applies equally to M4, HK416, and later weapons.

Old development-stage saved part ids are not migrated. Saves that still contain previous GunSmith part ids should be treated as invalid prototype data.

## Validation

Validation now checks weapon-level defaults:

- `weapon.defaults` must be a table when present.
- default slots must be platform root slots.
- default parts must exist.
- default part slots must match the root slot.
- default parts must be accepted by the platform root compatibility rules.
- `visual.relativeOffset` must contain numeric `x/y` when present.
- `mount.anchor` must contain numeric `x/y` when present.
- root-slot parts that use `visual.relativeOffset` are reported as warnings.

The existing validation commands remain:

```text
DeepGunsmithValidate
DeepGunsmithValidationSelfTest
```
