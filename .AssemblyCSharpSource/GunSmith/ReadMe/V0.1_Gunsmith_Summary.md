# Gunsmith V0.1 Summary

## Goal

V0.1 focuses only on `deep_m4`.

This version is meant to close the display loop proven in V0:

- keep the dedicated Gunsmith UI working
- keep Lua as the configuration source
- keep runtime texture composition working
- make both `InventorySprite` and `WorldSprite` follow part changes reliably

V0.1 does not expand to a second weapon, new slots, or stat systems.

## Result

V0.1 has been functionally validated on `deep_m4`.

Confirmed working:

- Gunsmith UI opens with `G`
- slot buttons cycle parts correctly
- `InventorySprite` updates with part changes
- `WorldSprite` now updates correctly as well
- dropped and held weapon visuals follow the selected parts

This means the V0 display loop is now closed for the first validation weapon.

## What Changed From V0

### 1. Separate world and inventory sprite creation

Runtime sprite creation is now split into two explicit paths:

- world sprite path
- inventory sprite path

The two paths still share the same composed runtime texture, but they no longer use the same clone rules.

### 2. World sprite cloning now follows prefab display intent more closely

The world sprite now preserves the original prefab sprite's display-side properties as much as possible:

- `Origin`
- `RelativeOrigin`
- `RelativeSize`
- `Depth`
- `SourceElement`
- `EntityIdentifier`
- `FilePath`

Because the runtime texture is not the original atlas, the source rectangle is adapted to the runtime texture while preserving the original display size as far as possible.

### 3. Active world sprite replacement now updates on part changes

V0's main display bug was not only the clone rule itself. Another issue was that a new `WorldSprite` state could be created while `item.activeSprite` still pointed to the previous custom sprite.

V0.1 updates that replacement chain so that:

- existing custom world sprites are replaced by the new custom world sprite
- inventory overrides still refresh normally
- old runtime textures are cleaned up after the new state has taken over

### 4. New-system weapon tag was formalized

Weapons handled by the new Gunsmith pipeline now use:

- `deep_gunsmith`

This tag is meant to distinguish the new modular gunsmith path from the older large-scale weapon set that still uses previous sprite logic.

For now, `deep_m4` is the first weapon using this tag.

### 5. Temporary V0 debug noise was reduced

Removed or reduced:

- per-open UI debug prints
- per-hook success prints
- temporary held-item debug output in Lua

Retained:

- hook bridge failure logs
- texture composition failure logs
- UI attachment failure logs
- world sprite application failure logs

## Current Expected Behavior

For `deep_m4`:

- press `G` to open Gunsmith UI
- click buttons to cycle parts
- `InventorySprite` updates
- dropped / held / world-side display updates correctly
- closing the UI should not reset current part selection

## Remaining Scope Boundary

Still out of scope for V0.1:

- second weapon support
- more platforms
- more slots
- attachment stat effects
- permanent save / network sync design
- final UI polish

## Notes For Next Version

If V0.1 fully stabilizes world rendering, the next meaningful step should be platform capability expansion rather than more low-level display debugging:

1. formalize per-platform display metadata
2. extend to another weapon on the same platform
3. add clearer selected-state / preview UI
