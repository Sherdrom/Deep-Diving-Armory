# Gunsmith V1.5 Summary

V1.5 starts the multiplayer synchronization pass for GunSmith saved selections. The main change is moving `GunsmithData.SavedState` synchronization onto Barotrauma's native item component event path instead of keeping GunSmith state as a client-only local bridge.

## Completed

- Upgraded `GunsmithData` to a native networked item component.
  - `GunsmithData` now implements `IClientSerializable` and `IServerSerializable`.
  - Clients can request the current server state through a component event.
  - Clients can submit an encoded saved state through the same component event path.
  - Servers write the authoritative saved state back through `item.CreateServerEvent(...)`.

- Kept the existing Lua persistence interface stable.
  - `DeepGunsmithRequestState`, `DeepGunsmithSaveState`, and `DeepGunsmithReceiveState` remain the public Lua-facing hooks.
  - Single-player continues using the local `GunsmithData.SavedState` path.
  - Multiplayer clients now route request/save operations through the server before receiving the final state.

- Added conservative saved-state validation.
  - Saved state payloads are capped at 8192 characters.
  - Empty state remains valid.
  - Non-empty state must match the current `{"v":1,"parts":{...}}` persistence envelope before the server accepts it.
  - The server rejects saves from clients that cannot access the item and broadcasts the current authoritative state instead.

## Deferred

- Full multiplayer validation with multiple human clients.
- Server-side reconstruction of GunSmith compatibility rules from Lua configuration.
- Server-authoritative runtime stat application beyond saved selection synchronization.
- Conflict handling beyond last accepted server state winning.

## Compatibility Notes

- The `GunsmithData.SavedState` serialized field and persisted JSON format are unchanged.
- GunSmith UI specs, quick UI specs, layer specs, and stat specs are unchanged.
- Existing single-player saves should continue loading through the same saved-state field.
- QuickMod hidden ItemContainer slots remain the real attachment storage path.

## Validation

- Initial local Debug testing did not show regressions in the V1.5 synchronization path.
- Source build verified:
  - `dotnet build .AssemblyCSharpSource/GunSmith/GunSmith.sln -m:1 /p:UseSharedCompilation=false /p:DebugType=None /p:DebugSymbols=false /p:ModDeployDir=.buildcheck\`
- Existing `ILuaCsHook.Add` deprecation warnings remain.
- Further validation still needs a multiplayer session with at least two clients.
