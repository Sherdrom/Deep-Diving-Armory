# Gunsmith V0.9.3 Summary

## Goal

V0.9.3 is a tuning and usability pass on the V0.9 receiver-led model. It focuses on world sprite transforms, scaled attach-point correctness, hidden receiver UI behavior, and AR test weapon visual calibration.

## Result

Implemented scope:

- Added per-weapon `world` sprite settings:
  - `scale`
  - `rotation`
  - `padding`
  - `offset = { x, y }`
- World sprites now use a separately baked texture derived from composed content bounds.
- Runtime signatures now include inventory and world sprite specs, so config-only visual tuning refreshes sprites.
- C# sprite state now owns and disposes `WorldTexture` separately from the composed source texture and inventory texture.
- Fixed scaled `visual.attachPoint` positioning: scaled parts now align by `attachPoint * visual.scale` instead of drifting from top-left scaling.
- Hidden receiver root now behaves as the UI home path:
  - home path label displays as `枪械 > 机匣`
  - returning from a receiver child path skips the hidden root page
  - returning to home reselects the slot the player just left
- Adjusted the GunSmith window columns to make the middle preview/detail panels visually centered.
- Tuned AR canvas height, visual origin, M4/HK416 root socket Y positions, optic mount anchors, and sight scale/order.
- Enabled the virtual receiver top rail's front optic mount.
- Renamed the left rail item prefab identifier to match the Lua config: `deep_gunsmith_AR_left_rail`.

## Schema

Weapon configs can now declare:

```lua
world = {
    scale = 1.0,
    rotation = 0.0,
    padding = 0,
    offset = { x = 0, y = 0 }
}
```

`world` only affects hand-held and dropped WorldSprite visuals. It does not affect GunSmith preview rendering or inventory icons.

## Validation

Validation now checks `weapon.world`:

- `scale` must be a positive number.
- `rotation` must be a number.
- `padding` must be a non-negative number.
- `offset`, when declared, must contain numeric `x/y`.

The self-test includes intentionally bad `world` values.
