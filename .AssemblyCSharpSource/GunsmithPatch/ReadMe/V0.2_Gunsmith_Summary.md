# Gunsmith V0.2 Summary

## Goal

V0.2 focuses on turning the V0.1 display prototype into a usable text-based Gunsmith UI flow.

This version still validates only `deep_m4`, but it adds the first version of nested part navigation:

- keep Lua as the configuration and selection source
- keep C# responsible for UI and runtime sprite composition
- keep the V0.1 `InventorySprite` / `WorldSprite` display loop working
- support part-provided mount points such as `handguard/top_rail/optic_mount`
- make the UI clear enough to continue expanding before final art and polish

V0.2 does not add stat effects, real part items, save data, network sync, or final image previews.

## Result

V0.2 has been functionally validated as a text-first nested UI prototype.

Confirmed working:

- Gunsmith UI opens with `G`
- the UI uses a left / middle / right layout
- left column selects the current slot in the current path level
- right column installs or removes parts for the selected slot
- middle column is split into a preview placeholder and a compact path/action panel
- path navigation supports examples like `枪械 > 护木 > 上导轨`
- nested mounts can be entered through the middle panel
- part changes still update the composed weapon visuals

## What Changed From V0.1

### 1. Text UI became a real three-column workflow

The old simple button list has been replaced with a structured layout:

- left: current-level slots
- middle top: weapon preview placeholder
- middle bottom: current path and optional enter button
- right: installable parts for the selected slot

The middle panel intentionally stays minimal:

- `路径: 枪械`
- `路径: 枪械 > 护木`
- `进入该配件挂点` only when the selected installed part provides child mounts

### 2. Nested part paths are now supported

Selections are no longer limited to flat root slots.

Examples:

- `handguard`
- `handguard/top_rail`
- `handguard/top_rail/optic_mount`

Lua validates these paths and removes invalid child selections when an upper part is changed or removed.

### 3. Parts can provide mount points

Parts may now declare optional `mounts`.

Current validation examples:

- handguards can provide `top_rail`, `bottom_rail`, `left_rail`, and `right_rail`
- top rails can provide `optic_mount`
- optic mounts can install placeholder optics such as red dot / holographic sights

Some V0.2 nested parts are text placeholders only. Parts without texture data participate in UI selection but do not add visual layers to the composed sprite.

### 4. Lua still owns data legality

C# does not understand the Gunsmith tree.

Lua is responsible for:

- current UI path
- valid child mounts
- path labels
- part compatibility by slot
- pruning invalid descendant selections
- flattening installed parts into the existing layer spec

C# only parses the UI spec, renders the window, and calls Lua hooks.

### 5. Hook behavior was extended without replacing V0.1

Existing hooks remain:

- `DeepGunsmithApply`
- `DeepGunsmithOpen`
- `DeepGunsmithSetPart`
- `DeepGunsmithCycle`

V0.2 adds:

- `DeepGunsmithEnterPath`

This hook changes only the UI navigation path and then reopens the UI.

## Current Expected Behavior

For `deep_m4`:

- press `G` to open Gunsmith UI
- select `护木` on the left
- install a handguard on the right
- use the lower middle panel to enter the installed part's mount points
- install a rail under `枪械 > 护木 > 上导轨`
- enter the rail's mount point
- install a text placeholder optic under `枪械 > 护木 > 上导轨 > 瞄具挂点`

Changing or removing an upper-level part should clear child selections that are no longer valid.

## Remaining Scope Boundary

Still out of scope for V0.2:

- final visual polish
- part icons or image previews
- drag-and-drop install behavior
- physical part items
- save / load persistence
- multiplayer synchronization
- stat effects
- compatibility rules beyond slot matching
- second weapon support
- workbench / station entry

## Notes For Next Version

The next useful step is likely to refine either:

1. UI details and final interaction polish
2. config schema clarity for real art production
3. persistence / synchronization design
4. real attachment behavior and stat effects
